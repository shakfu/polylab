Managed state

Notes live in a Mutex inside Rust, registered with Builder::manage. The frontend holds no copy of the list -- it re-reads it after every mutation.

    Rust to frontend events

    A background task in setup() emits app://tick every second; the webview subscribes with listen(). Unlike commands, events are one-way and fan out to every window.

    Frontend to Rust events

    emit("ui://log", payload) is fire-and-forget in the other direction. Rust prints it to the terminal running tauri dev.

    Streaming progress over a channel

    One invoke, many messages: run_job takes an ipc::Channel and sends a tagged enum per step. Cancellation is a second command flipping an AtomicBool the job polls.

    Native dialogs

    The dialog plugin returns a path; the file itself is read by a Rust command. Rust is not bound by the frontend's filesystem scope, which is what makes "open anything the user picked" workable.

    Scoped filesystem access

    This scratchpad uses the fs plugin directly from JS with BaseDirectory.AppData. It only works because capabilities/default.json grants read and write under $APPDATA -- try changing the path and the call is denied.

    Controlling this window

    Each call maps to one permission in the capability file. Without core:window:allow-set-fullscreen, for example, the fullscreen button throws instead of doing nothing.

    Extra webview windows

    A Tauri app is multi-window. Each window is a separate webview with its own label, and events reach all of them.

    Close behaviour

    With "close to tray" enabled (see Settings), Rust intercepts CloseRequested and hides the window instead of quitting. The tray icon brings it back.
